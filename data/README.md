# 데이터 수집 가이드 (시군구 단위)

> **기준 시점: 2025년 12월 31일 (2026.7.1 인천 행정구역 개편 이전 경계)**
> 모든 파일은 이 시점(연간 통계는 2025년) 기준으로 받는다. 분석 단위는 일반구를 상위 시로 합친 기초자치단체 약 229개다.

실행 순서:
1. `python -m src.population`: 행안부 파일로 아래 두 CSV를 만든다.
   - 기준 코드표 `data/processed/population_sigungu_202512.csv`
   - 1인세대 `data/processed/single_household_sigungu_202512.csv`
2. `python -m src.disability`: KOSIS 등록장애인 파일로 `data/processed/disability_sigungu_2025.csv` 를 만든다.
3. `python -m src.fetch_emergency`: 응급의료기관 OpenAPI로 `data/processed/emergency_facilities.csv` 를 만든다.
4. `python scripts/build_boundaries.py`: 행정동 경계(admdongkor)를 받고 시군구 경계를 만든다 (5절).
5. `python -m src.emd_centers`: 행정동 기준점(행정복지센터) `data/processed/emd_centers.csv` 를 만든다(카카오, 캐시).
6. `python -m src.fetch_emd_population 202512`: 행정동 인구 OpenAPI로 `data/processed/emd_population_202512.csv` 를 만든다.
7. `python -m src.emd_centers --population 202512`: 행정동 인구를 기준점에 붙이고 시군구 합계를 검증한다.
8. `python -m src.emd_islands 202512`: 섬 읍·면의 리(섬) 좌표·인구 `data/processed/emd_li_points.csv` 를 만든다.
9. (WSL, Docker Engine) `bash scripts/osrm_setup.sh serve`: 로컬 OSRM을 준비하고 localhost:5000 에 띄운다 (3-4절).
10. `python -m src.drivetime`: 기준점 × 가까운 기관 주행시간 `data/processed/drivetime_pairs.csv` 를 만든다.
11. `python -m src.accessibility`: 접근성 지표 `data/processed/accessibility_sigungu.csv` 를 만든다.
12. `python -m src.build_table`: 위 표들을 행정기관코드로 합쳐 `data/processed/sigungu_table.csv` 를 만든다.
13. `python -m src.emd_metrics`: 읍면동 드릴다운 지표 `data/processed/emd_metrics.csv` 를 만든다 (3-6절).
14. `python scripts/build_emd_boundaries.py`: 행정동 경계를 시군구별 파일 `web/public/data/emd/{시군구코드}.json` 으로 나눈다.

3·5·6번은 레포 루트의 `.env` 에 키가 있어야 한다(`.env` 는 .gitignore, 절대 커밋하지 않음). `.env.example` 을 복사해 채운다.

```
DATA_GO_KR_SERVICE_KEY=공공데이터포털 일반 인증키 (Encoding/Decoding 어느 쪽이든 됨)
KAKAO_REST_API_KEY=카카오 디벨로퍼스 REST API 키 (카카오맵 사용 설정 필요)
```

공공데이터포털 키는 `DATA_GO_KR_SERVICE_KEY` 를 먼저 읽고, 없으면 `KR_SERVICE_KEY` 를 읽는다(`src.fetch_emergency.service_key`, 환경변수도 됨).

**버전관리**: `data/raw/` 는 git에 올리지 않는다(.gitignore). raw 파일은 아래 각 항목의 "받는 방법"을 참고해 직접 받는다. `data/processed/*.csv` 는 커밋한다.

```

│   ├── single_household/202512_202512_행정동별 성연령별 주민등록 1인세대수_{지역}.xlsx  # 시도별 16개 + 전국 1개
│   ├── disability/시군구별_장애정도별_성별_등록장애인수.xlsx  # KOSIS DT_11761_N009
│   ├── emergency/보건복지부_응급의료기관 수_시도별_20241231.csv  # 검증용 (시도별 등급별 기관 수)
```

## 데이터 한계

- **읍면동은 접근성·고령만**: 독거노인·장애인 비율은 읍면동 공개 통계가 없어 시군구 값만 쓴다. 읍면동 고령 비율은 10세 단위 인구에서 60대를 시군구 비율로 나눈 추정치다(3-6절).
- **1인세대 ≠ 실제 단독 거주**: 독거노인 수는 주민등록상 65세 이상 1인세대 수다. 같은 집에 살아도 세대를 나눠 등록하면 1인세대로 잡혀서, 실제로 혼자 사는 노인 수와 다를 수 있다.
- **일반구는 상위 시로 합산**: 수원시 장안구 같은 일반구는 상위 시(수원시)로 합쳤다. 그래서 같은 시 안의 구별 차이는 보이지 않는다. 분석 단위는 기초자치단체 229개다.
- **기준 시점 2025년 12월 (인천 개편 전)**: 2026.7.1 인천 행정구역 개편(제물포구, 영종구, 검단구 신설) 이전 경계다. 개편 후 경계 기준의 결과와는 다르다.
- **기초생활수급자 제외**: 시군구 단위 전국 공개 통계가 없어 분석에서 뺐다. KOSIS(DT_11714_N001)에는 시도 단위까지만 공개돼 있다.
- **주행시간은 자유 주행 기준**: OSRM 자동차 프로필의 도로 등급별 속도로 잰 값이다. 실시간 교통(정체·시간대), 구급차 우선통행·신호 무시, 도로 공사는 반영하지 않는다. OSM 도로 속성(제한속도 누락 등)이 빠진 곳은 기본 속도를 쓴다.
- **연륙 안 된 섬·해상 이동 미반영**: 페리는 빼고 계산해, 다리가 없는 섬(기준점 235곳)은 도로로 기관에 닿지 않는다. 이런 쌍은 직선거리 × 시군구 우회계수로 근사하므로 배·헬기 이동(운항 시간, 기상)을 반영하지 못한다. 옹진(인구 38%)·완도(36%)·신안(34%)·진도(10%) 등은 실제 접근성이 수치보다 나쁘다. 근사값은 도로로 잰 주행시간의 99백분위(126.2분)에서 잘라 점수·범례·K-means에 쓰므로 실제 시간의 하한이다(울릉 센터는 자르기 전 365분, `*_분_원값` 컬럼). 근사값을 쓰는 주민 비율은 `근사반영_인구비율` 이다(울릉 100%, 신안 68%, 옹진 61%, 완도 36%).
- **가까운 10곳 밖은 근사**: 기준점마다 직선거리 가까운 응급의료기관 10곳 + 센터 10곳만 실제 주행시간을 잰다. 나머지(주로 30분 내 기관 수에 영향)와 시뮬레이터로 추가한 가상 기관은 우회계수 근사다.
- **기준점은 행정동 행정복지센터 한 점**: 시군구 지표는 행정동 3,557곳의 거리를 인구로 가중평균한 값이다. 넓은 읍·면 안의 마을별 거리 차이는 남는다. 섬 읍·면 62곳은 리(섬) 단위로 나눴다. 행정복지센터를 못 찾은 행정동 44곳(모두 동 지역)은 경계 내부 대표점을 쓴다.
- **시군구 경계 기준 기관 수 제외**: `인구10만명당_응급의료기관수` 는 시군구 경계 안의 기관만 세서 소면적·고밀도 도심을 과소평가한다(예: 서울 마포구 0곳, 관악구 0.21곳). 그래서 접근성 점수와 클러스터링에서 뺐고, 테이블 컬럼으로만 남겨 둔다.
- **30분 내 기관 수는 기준점 위치에 민감**: 접근성 점수에 들어가는 30분 내 기관 수는 기준점을 조금만 옮겨도 바뀐다. 행정동 인구가중으로 한 점에 대한 민감도는 줄었지만, 30분 경계 근처 기관 하나로 값이 바뀌는 성질은 남아 있다.
- **기준선 근처 지역은 등급이 바뀔 수 있음**: 이중 취약은 상위 25% 기준선으로 나눈다. 기준선 바로 위·아래 지역(예: 강원 고성 복지 75.55점 vs 기준 75.5점)은 기준이나 데이터 시점이 조금만 바뀌어도 등급이 달라진다.
- (해소됨) **청사 옆 병원 과소 추정, 시군구청 기준점 편향**: 예전 시군구청 1점 기준에서는 청사 옆 병원 때문에 최근접 거리가 0.1~0.2km로 나오고(거창·단양·화천 등), 시뮬레이터 추천이 시군구청 위치에 유리했다. 행정동 인구가중으로 바꾸면서 해소됐다 (README "기준점 변경에 따른 결과 변화").
- **기관 기준 시점 차이**: 응급의료기관은 API 수집일 기준(2026-11-04)이고 인구는 2025년 12월 기준이다.
- **국토모니터링 공식 지표 미사용**: 국토지리정보원 국토모니터링 "응급의료시설 접근성"은 다운로드 프로그램 문제로 받을 수 없어 직접 계산했다.

## 향후 개선

- (완료) **전국 읍면동 인구가중 기준점**: 행정동 3,557곳 행정복지센터 + 행정동 인구 API로 적용했다(#10).
- **마을·격자 단위 기준점**: 행정동 한 점 대신 통·반 또는 인구 격자 단위로 더 잘게 나눈다.
- (완료) **도로 네트워크 시간**: 로컬 OSRM 자동차 주행시간으로 바꿨다(#19).
- **해상 이동 반영**: 여객선 운항 시간표·응급 헬기 이송 시간을 섬 기준점에 더한다.
- **시간대별 교통**: 실측 교통량·구급차 출동 기록으로 주행시간을 보정한다.
- **2SFCA 기반 공급/수요 접근성**: 시군구 경계 기준 "인구 대비 기관 수" 대신 2단계 유동 영역(Two-Step Floating Catchment Area) 지표를 쓴다. 기관별로 반경 안 인구 대비 공급(병상·인력)을 구하고, 지역별로 반경 안 기관 공급을 합쳐서 경계와 무관하게 공급/수요를 함께 반영한다.

## 공통 규칙

- 지역 매칭은 **(시도명, 시군구명)** 으로 한다. KOSIS는 통계청 행정구역코드를 써서 행안부 코드와 값이 다르기 때문이다. 시도명은 `경기도`, `경기` 둘 다 되고, 시군구명의 띄어쓰기는 무시한다.
- 분석 단위는 기초자치단체(약 229개)이고, 일반구(수원시 장안구 등)는 상위 시로 합친다.
- 행안부 파일의 컬럼명은 공백·괄호·특수문자를 뺀 이름으로 비교한다(예: `총 인구수` → `총인구수`).
- 시도 칸이 첫 행에만 있어도 괜찮다(아래로 채워 넣음). `소계`, `계`, `합계` 행은 자동으로 뺀다.
- 각 스크립트가 매칭 실패와 빠진 시군구를 직접 출력한다. `build_table` 은 이미 코드가 붙은 표를 합치기만 한다.

## 1. 인구: `population/202512_202512_연령별인구현황_{지역}.xlsx`

- **출처**: 행정안전부 주민등록 인구통계 (https://jumin.mois.go.kr)
- **받는 방법**:
  1. **연령별 인구현황** 메뉴로 간다.
  2. 행정구역에서 **시도를 하나씩 고르고**(하위 시군구 전체 포함) 받는다. 받으면 파일 하나에 시도 합계 행과 그 시도의 시군구 행이 들어 있다.
  3. 연령구분 단위는 **5세**, 연령 범위는 **0~4세부터 100세 이상까지 전체**로 고른다.
  4. 조회 기간은 **2025년 12월(월간)** 으로 고르고, 엑셀로 내려받는다.
  5. 같은 설정으로 행정구역 **전국**(전국과 시도 합계)도 받는다. 이 파일은 검증용이다.
- **파일명**: 받은 그대로 `202512_202512_연령별인구현황_{지역}.xlsx` 로 둔다. 지역 이름은 아래 16개 + `전국` 이다.
  - 서울, 부산, 대구, 인천, 전남광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 경북, 경남, 제주
  - `전남광주` 파일에는 광주광역시(29…)와 전라남도(46…)가 함께 들어 있고, 따로 나눌 필요는 없다.
- **파일 구조**(`src/population.py` 가 이 구조를 전제로 읽는다):
  - 0~2행은 안내문, 기준월, 계/남/여 머리글이고, 3행(0부터 셈)이 헤더다.
  - 헤더는 `행정기관코드, 행정기관, 총 인구수, 연령구간인구수, 0~4세 … 100세 이상` 이고, 계 → 남 → 여 블록으로 반복된다. **계 블록만** 쓴다.
  - 숫자는 쉼표가 들어간 문자열이다. 행정기관코드는 10자리이고, 뒤 8자리가 `00000000` 이면 시도 합계 행이라 뺀다.
- **결과**: `data/processed/population_sigungu_202512.csv`
  - 컬럼: `행정기관코드`(5자리), `시도`, `시군구`, `총인구`, `65세이상인구`, `80세이상인구`
  - 일반구는 상위 시로 합친다. 시 합계 행과 일반구 행이 함께 있으면 시 합계 행만 쓴다.
  - 검증: 시도별 시군구 합 = 전국 파일의 시도 총인구, 전국 합 = 51,117,378명. 맞지 않으면 시도와 차이를 출력한다.
- **주의**:
  - 이 파일이 **기준 코드표**다. 다른 출처는 모두 이 파일의 (시도, 시군구) 이름에 맞춘다.
  - 연령 범위를 일부만 고르면 65·80세 이상 컬럼이 없어서 경고가 나고 해당 값이 빈칸이 된다.
  - KOSIS의 "행정구역(시군구)별/5세별 주민등록인구"는 행안부 코드 컬럼이 없어서 이 자리에 쓸 수 없다.

### 3-4. 자동차 주행시간: `processed/drivetime_pairs.csv` (`python -m src.drivetime`)

  - 실주행시간이 있는 쌍은 그 값을 쓴다. 없는 쌍(10곳 밖, 도로 미연결, 가상 기관)은 직선거리 × 시군구 우회계수다.
  - 우회계수(분/직선km): 기준점마다 도로로 닿는 가장 가까운 기관(직선 1km 이상)의 주행분/직선km를 구하고, 시군구 중앙값을 쓴다(값이 없으면 전국 중앙값). 소수 3자리로 반올림한다.
  - 근사값 상한: 실주행 쌍 주행시간의 99백분위(`근사상한_분`, 이번 126.2분). 근사값만 자르고 실주행값은 그대로 둔다. 웹 `baseline.json` 의 `근사상한분` 도 같은 값이다.

- **가까운 기관 순위** (`processed/facility_rank.csv`, 행정동은 `emd_facility_rank.csv`): 시군구(행정동)마다 화면에 보일 기관 목록. 주민 평균 주행시간(근사값 상한 적용, 같으면 자르기 전 평균) 짧은 순 응급의료기관 3곳·센터 2곳에, 이용 주민 비율 10% 이상인 기관을 항상 더한다(최대 5곳, 넘치면 상위 목록의 대안부터 뺌, `pick_list`). 컬럼: 순위(목록 안), 시간순위(전체), 이용 주민 비율(없으면 0 = 대안), 근사·상한 포함 여부, 이용주민평균주행분·이용주민상한포함(그 기관이 최근접인 주민만의 평균, 대안은 빈칸). 대시보드 목록과 같은지 vitest로 검증한다.
- **이용 기관** (`processed/facility_usage.csv`): 기준점마다 주행시간이 가장 짧은 응급의료기관과 권역·지역센터를 정하고(근사값 상한에 걸린 동률은 자르기 전 값이 작은 기관), 시군구 인구 기준으로 기관별 이용 주민 비율·그 주민의 평균 주행분·평균 직선km·근사 포함 여부를 낸다. 시군구 밖 기관도 포함하고, 웹(`facilityUsage`)과 같은지 vitest로 검증한다.
- 거리는 하버사인 공식(지구 반지름 6,371km)으로 잰다. 기준점(행정동, 섬 읍·면은 리)별 지표를 인구로 가중평균한다.
- 검증 출력 항목:
  - 등급별 개수, 매칭 실패, 보건복지부 2024 시도별 비교, legacy 비교
  - 좌표가 한국 범위(위도 33~38.7, 경도 124.5~132) 안인지
  - 주행시간 상위·하위 10개 시군구

### 3-6. 읍면동 드릴다운: `processed/emd_metrics.csv` (`python -m src.emd_metrics`)

시군구 판정에는 쓰지 않고, 대시보드에서 시군구 안의 편차를 보는 데만 쓴다.

- **입력**: `processed/accessibility_points.csv`(기준점 4,066곳의 주행시간 지표·최근접 기관, `src.accessibility` 가 저장), 행정동 인구 API 캐시(10세 단위 연령), 시군구 65세 이상 인구
- **지표**: 기준점 지표를 행정동 인구로 가중평균한다(섬 읍·면은 리 기준점을 소속 읍·면으로). 인구는 API 행정동 합계를 쓴다. 좌표 없는 섬 리 때문에 주행시간 가중치가 4명 적은 행정동이 1곳 있다.
- **고령(65세 이상) 추정**: API가 10세 단위라, 시군구마다 r = (시군구 65세 이상 − 70세 이상) / 60대 를 구해 행정동 65세 이상 = 70세 이상 + 60대 × r 로 나눈다. r 은 0.41~0.54(중앙값 0.50)이고, 행정동 합은 시군구 65세 이상과 같다.
- **접근성 점수·구간**: 시군구와 같은 3개 지표(최근접 응급의료기관·센터 주행분, 30분 내 기관 수)의 전국 행정동 3,557곳 백분위 평균. 사분위로 상위 25% / 상위 25~50% / 하위 25~50% / **하위 25%**(경계 27.94·47.41·72.33점)
- **이용 기관**: `processed/emd_usage.csv` (시군구 `facility_usage.csv` 와 같은 집계를 행정동 단위로)
- **섬 리**: `processed/emd_li_metrics.csv` (리별 인구·고령 비율)
- **웹**: `emd.json`(행정동 고정값·전국 분포 217KB)과 `centers.json` 기준점의 `emd` 로 브라우저가 다시 계산하고, Python 결과와 같은지 vitest로 검증한다. 경계는 `scripts/build_emd_boundaries.py` 가 mapshaper로 꼭짓점 40%를 남기게 단순화해 시군구별 229개 파일(합계 6.6MB, 중앙값 30KB, 최대 108KB)로 나눈다. 15%(3.1MB)는 작은 구를 최대로 확대하면 동 경계가 각져 보여 올렸다. 원본(admdongkor)도 동마다 꼭짓점이 수십 개 수준이라(서울 중구 15개 동 666개 → 284개), 더 확대해도 원본보다 매끈해지지는 않는다.

### 4-1. 등록장애인: `disability/시군구별_장애정도별_성별_등록장애인수.xlsx`

- **출처**: 보건복지부 「장애인현황」, KOSIS 통계표 **DT_11761_N009** "시군구별, 장애정도별, 성별 등록장애인수"
  - URL: https://kosis.kr/statHtml/statHtml.do?orgId=117&tblId=DT_11761_N009&conn_path=I3 (KOSIS 개편 시 바뀔 수 있음)
- **받는 방법**:
  1. 위 URL로 통계표를 연다.
  2. 조회 설정에서 시점은 **2025년**(연말 기준), 시군구는 **전체**로 고른다.
  3. 장애정도는 **합계**, 성별은 **계**만 고른다.
  4. 엑셀로 내려받는다. 시트는 `데이터`, `메타정보` 두 개다.
- **파일 구조**(`src/disability.py` 가 이 구조를 전제로 읽는다):
  - `데이터` 시트의 0~2행은 머리글이고, 3행부터 데이터다.
  - 열은 시도명 / 시군구명 / 등록장애인 수 순서다. 시도명은 첫 행에만 있다.
  - `소계` 는 시도 합계라 뺀다. 다만 세종은 `소계` 행 하나뿐이라 그 값을 세종 값으로 쓴다.
  - 일반구는 `수원시장안구` 처럼 붙여 쓰고 상위 시 합계 행이 없다. 그래서 구 행을 합쳐 상위 시로 만든다.
  - `메타정보` 시트는 출처 기록용이라 읽지 않는다.
- **결과**: `data/processed/disability_sigungu_2025.csv` (행정기관코드 5자리, 시도, 시군구, 등록장애인수)
  - 검증 1: 시군구 합 = 파일의 전국 소계 = 2,627,761명
  - 검증 2: 인구 기준 코드표와 1:1 매칭. 매칭 실패 행과 값이 빠진 시군구를 출력한다.
- **파생 지표**: `sigungu_table.csv` 의 `장애인비율` = 등록장애인수 ÷ 총인구 (0~1 비율)
